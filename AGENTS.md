# Repository Guidelines

## Project Structure and Module Organization

The repository root is the primary AWS RDS Aurora Terraform module. Keep root
resources in `main.tf`, inputs in `variables.tf`, outputs in `outputs.tf`, and
Terraform/provider constraints in `versions.tf`. `modules/dsql/` contains the
DSQL submodule, `examples/` contains runnable usage configurations, and
`wrappers/` contains wrapper modules. Supporting upgrade and provenance notes
live in `docs/` and `UPSTREAM.md`; GitHub Actions workflows live in
`.github/workflows/`.

The module requires Terraform `>= 1.11.1` and the HashiCorp AWS provider
`>= 6.28`. Do not change these constraints incidentally.

## Development and Validation Commands

- `terraform fmt -check -recursive` checks HCL formatting across all Terraform
  roots.
- `terraform init -backend=false` initializes a Terraform root for local
  validation without configuring remote state.
- `terraform validate` validates the initialized Terraform root.
- `pre-commit run --all-files` runs the repository-configured formatting,
  documentation, TFLint, validation, whitespace, and merge-conflict hooks.

Run validation from the Terraform root affected by a change. Changes to shared
root-module behavior should also be exercised through the most relevant example.

This is a reusable module repository, not a deployment environment. Do not run
`terraform apply`, `terraform destroy`, import commands, or Terraform state
mutation commands without explicit authorization. Keep `.terraform/`, state and
plan files, crash logs, `.tfvars`, and `.terraform.lock.hcl` out of version
control; several may contain sensitive data.

## Coding Style and Naming

Use two-space indentation for Terraform and follow `terraform fmt`. Keep module
files organized by their existing responsibilities and follow surrounding HCL
naming patterns. Document every input and output; the configured TFLint checks
also enforce typed variables and standard module structure. EditorConfig
requires UTF-8, LF line endings, final newlines, and no trailing whitespace
outside Markdown.

The sections delimited by `BEGIN_TF_DOCS` and `END_TF_DOCS` in the root and DSQL
READMEs are generated by the configured `terraform_docs` pre-commit hook. Change
the Terraform source and regenerate those sections instead of editing generated
content by hand.

## Testing Guidelines

Treat formatting, linting, generated-document checks, and `terraform validate`
as the baseline for Terraform changes. Validate each changed Terraform root,
including affected examples, submodules, or wrappers. Tests and validation must
not require access to a live AWS account unless the task explicitly calls for
integration testing.

## Upstream Provenance

This repository is an independently maintained derivative of upstream tag
`v10.2.0`. Preserve existing derivative modification notices on changed
upstream-derived files. Follow `UPSTREAM.md` for future imports: use a sanitized
snapshot of a verified immutable upstream revision and do not merge upstream Git
history into this repository.

## Commit and Pull Request Guidelines

Recent commits use short Conventional Commit-style subjects such as `docs:`.
GitHub accepts PR title types `fix`, `feat`, `docs`, `ci`, and `chore`, with a
subject beginning with an uppercase letter. Keep pull requests focused and
describe user-visible module behavior, compatibility effects, and validation
performed.
